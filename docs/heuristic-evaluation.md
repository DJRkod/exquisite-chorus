# Heuristic evaluation sheet: Nov 17

Other groups use this sheet to evaluate the Exquisite Chorus prototype in class. One of us shares the screen over Zoom and hands mouse control to the evaluator. Another of us fills in the findings table below.

## Before the session

- Open `prototype/index.html` in Chrome or Firefox. Double-clicking the file works, and it needs no install or server.
- The **Prototype tasks** button in the bottom-right corner starts each task fresh. Use it between evaluators.
- Nothing is saved and no audio plays. File pickers choose a sample file instead of opening your computer's files.

## Tasks for the evaluator

Read each task aloud. Don't explain how to do it; where the evaluator gets stuck is the finding.

1. **Sign up and choose what you play.** You play guitar and keys. Create an account.
2. **Start a project.** You have an unfinished track called "Night Shift" and want someone to add bass and vocals. Post it.
3. **Contribute to a project.** Find a project that needs something you play, get its current mix, and send back your version with your part added.

## Nielsen's 10 usability heuristics

Rate problems against these.

| # | Heuristic | Ask |
|---|---|---|
| 1 | Visibility of system status | Does the evaluator always know what just happened and what's happening now? |
| 2 | Match between the system and the real world | Do the words match how musicians talk (mix, part, BPM, key)? |
| 3 | User control and freedom | Can they back out of a step or undo a choice? |
| 4 | Consistency and standards | Do the same things look and behave the same on every screen? |
| 5 | Error prevention | Does the design stop mistakes before they happen? |
| 6 | Recognition rather than recall | Is what they need visible, or do they have to remember it from an earlier screen? |
| 7 | Flexibility and efficiency of use | Can someone who knows the app move faster? |
| 8 | Aesthetic and minimalist design | Does every element on a screen earn its place? |
| 9 | Help users recognize, diagnose, and recover from errors | Do error messages say what went wrong and how to fix it? |
| 10 | Help and documentation | When they're unsure, is there help where they need it? |

## Severity

| Rating | Meaning |
|---|---|
| 0 | Not a usability problem |
| 1 | Cosmetic: fix if there's time |
| 2 | Minor: low priority |
| 3 | Major: important to fix |
| 4 | Catastrophe: must fix before release |
